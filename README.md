# מערכת ניהול מחזור חיי נסיעה

מימוש **שלב 1** מסעיף 11 באפיון: תיק, נוסעים, רכיבים, מנוע אבני הדרך עם תבנית
אחת (חבילת נופש רגילה), ומסך "היום".

המטרה של השלב הזה, כלשון האפיון, היא לבדוק שהתור באמת עובד — לכן אין עדיין
עמוד לקוח, אין הודעות וואטסאפ, ואין פאנל כספים מלא.

## הרצה

```bash
npm install
cp .env.example .env          # ואז למלא PASSPORT_ENCRYPTION_KEY
npm run db:push               # יצירת מסד הנתונים
npm run db:seed               # שלושה תיקי הדגמה (אופציונלי)
npm run dev                   # http://localhost:3000
```

ליצירת מפתח ההצפנה:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

פקודות נוספות:

```bash
npm test          # 59 בדיקות יחידה על מנוע אבני הדרך וחישובי הזמן
npm run typecheck
npm run job:daily # ה-job היומי (סעיף 10) — אפשר גם POST /api/jobs/daily
```

## מה אפשר לערוך בלי מפתח

שלושה קובצי נתונים ב-`config/`, כפי שהאפיון דורש:

- `config/templates/leisure-package.json` — אבני הדרך: כותרת, קהל, עוגן, היסט,
  חלון התראה, חסימות והשלמה אוטומטית. הוספת תבנית = הוספת קובץ ורישום שלו
  ב-`src/lib/milestones/template.ts`. כל תבנית מאומתת בעלייה, ושגיאה בה נופלת
  מיד עם הודעה בעברית ולא בשקט.
- `config/data/airline-checkin-rules.json` — חלונות הצ'ק-אין לפי חברת תעופה.
  **המספרים כאן הם ניחוש סביר ולא מקור אמת — צריך לעבור עליהם.**
- `config/data/airports.json` — אזור הזמן של כל שדה. שדה שלא מופיע כאן ייחסם
  ביצירת תיק, כדי שלא תיווצר הנחת אזור זמן שגויה.

## החלטות שהתקבלו

**סטאק.** Next.js + Prisma + SQLite, שכבה אחת שתשרת בהמשך גם את עמוד הלקוח
(סעיף 10). SQLite מספיק לשני משתמשים; מעבר ל-Postgres הוא שינוי שורה אחת
ב-`schema.prisma`. אין Tailwind ואין ספריית תאריכים — RTL וזמנים נכתבו ידנית
כי שניהם קריטיים ולא רציתי להסתיר אותם מאחורי הפשטה.

**אזורי זמן.** כל זמן שנתון בשעון שדה תעופה נשמר כזוג (שעה מקומית נאיבית,
אזור IANA) וה-UTC נגזר ממנו. חלונות הצ'ק-אין נגזרים משעון שדה היציאה.
מטופלים גם השעה שאינה קיימת במעבר לשעון קיץ והשעה הכפולה בחזרה ממנו.
הבדיקות ב-`tests/zones.test.ts` כוללות טיסה מבנגקוק, שבה חישוב בשעון ישראל
היה נותן תשובה שגויה ב-5 שעות.

**הצמדה לשעת עבודה.** אבני דרך ברזולוציית ימים מוצמדות ל-09:00 שעון ישראל
(ניתן לשינוי בתבנית), אחרת התור מתמלא בפריטים ב-23:40 רק כי כך יצא מההיסט.
ההצמדה לעולם לא מקדימה את העוגן עצמו — תיק שנפתח ב-13:00 לא נולד עם אסמכתא
שעברה את מועדה ב-09:00, ו"ברוכים השבים" לא נשלח לפני הנחיתה.

**תיק שנוצר מאוחר (סעיף 14).** אבני דרך שנולדות אחרי מועדן מסומנות ומקובצות
לשורה מתקפלת אחת במקום 12 שורות אדומות. שני סוגים **אף פעם** לא מקובצים,
כי הם בדיוק הכשלים הכספיים מסעיף 2: בעיית תוקף דרכון, ומועד ביטול חינם שעבר.

**ביטוח.** אבן הדרך של סגירת הביטוח לא ניתנת לוויתור. הכפתור פותח בחירה בין
נרכש דרכנו / הלקוח סירב / נרכש מחוץ לסוכנות, וההכרעה נשמרת עם תאריך.

**דחייה זמנית.** גם היא מחייבת סיבה, לא רק ויתור — סעיף 12 דורש ששום אבן דרך
לא תיעלם מהמסך בלי טיפול או סיבה.

**רכיב שהלקוח סירב לו** נספר כ"סגור" לצורך חסימת המסמכים. האפיון מדבר על
`confirmed` או `cancelled` בלבד, אבל בלי זה הצעת upsell שהלקוח דחה הייתה
חוסמת את שליחת המסמכים לנצח.

**פרטים אישיים.** מספרי דרכון מוצפנים ב-AES-256-GCM עם מפתח מהסביבה, ונמחקים
בסגירת תיק. תאריכי התוקף נשארים, כי הם נדרשים להזמנה הבאה ואינם מזהים
כשלעצמם.

## תשובות שהתקבלו לסעיף 13

- **נפח:** 100+ תיקים פעילים בשיא. לכן `dueAt` מחושב בכתיבה, יש אינדקס על
  `(state, dueAt)`, והשאילתה של מסך היום חסומה בתקרה. מסך ציר הזמן (שלב 3)
  יצטרך סינון ועימוד מלאים.
- **פרטי נוסעים:** מותר להחזיק, עם הצפנה. מומש כך.
- **בעלות על תיקים:** שני הסוכנים עובדים על אותם תיקים. אין שדה owner ואין
  מסנן "שלי" — בדיוק כמו הלא-מטרות של v1.

## מה עוד פתוח (סעיף 13)

1. **מה מגיע מ-Travel Or ובאיזה פורמט?** משפיע על שלב 5 (קליטה אוטומטית של
   פרטי טיסה). כרגע הכל ידני.
2. **תבנית 7א מול הזמנות אמיתיות.** התבנית מומשה כלשונה, אבל האפיון עצמו אומר
   שהיא ברירת מחדל בלבד. כדאי לעבור עליה מול שתיים-שלוש הזמנות מהחודשים
   האחרונים ולראות מה חסר ומה מיותר.
3. **עם אילו חברות תעופה עובדים בפועל?** `airline-checkin-rules.json` מכיל
   23 חברות עם מספרים סבירים שלא אומתו. טעות כאן = צ'ק-אין שנסגר.
4. **מה החלוקה בין נופש, ספורט וקרוז?** קובעת אם תבנית ב׳ או ג׳ קודמת.

## הנחות שכדאי לאשר

- שעת ברירת המחדל לאבני דרך יומיות היא 09:00 שעון ישראל, ולכל אבן דרך אפשר
  לקבוע שעה משלה בתבנית.
- אבן דרך של "צ'ק-אין אמצע חופשה" מתוזמנת גם היא לשעון ישראל ולא לשעון היעד.
  לסוכן זה נכון, ללקוח שנמצא בבנגקוק פחות. אם רוצים לפי שעון היעד — זה שינוי
  קטן, אבל צריך להחליט.
- דדליין של ספק (ביטול חינם / תשלום) מקבל התראה שלושה ימים מראש.
- "עד סוף השבוע" במסך היום = עד סוף שבת.
- מספר התיק נגזר מחודש היציאה ומונה רץ, למשל `2609-114`.

## מה הלאה (סעיפים 11.2–11.5)

- **שלב 2 — תקשורת.** תבניות הודעות כקבצים ניתנים לעריכה, וכפתור שפותח את
  וואטסאפ עם ההודעה מוכנה (`wa.me` עם טקסט מקודד). התשתית קיימת:
  לכל אבן דרך יש כבר `messageTemplateKey`.
- **שלב 3 — שליטה.** ציר הזמן האופקי של כל התיקים, ופאנל כספים מלא.
- **שלב 4 — הלקוח.** עמוד web בקישור ייחודי.
- **שלב 5 — הרחבה.** תבניות ספורט וקרוז. המנוע כבר תומך בעוגן `event`
  ובעוגנים כפולים; חסרות רק התבניות עצמן והשדות בטופס.
